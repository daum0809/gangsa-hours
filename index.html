강사료 계산을 자동화하다가 배운 것들

학원 강사 11명의 근무시간을 카톡으로 받아 엑셀에 옮겨 적던 월말 30분을, 링크 하나로 바꾼 기록.

1. 실패한 것부터

처음 만든 건 이게 아니었습니다. 자영업 사장님을 위한 '문구 생성 앱'이었습니다. 리뷰 악평에 답글을 달아주고, 홍보 문구를 세 가지 말투로 뽑아주고, 광고법 위험 표현까지 걸러주는 물건이었습니다. 기술적으로는 그럴듯했습니다.

써보고 접었습니다. 원장이 직접 쓰는 게 더 빨랐기 때문입니다.

여기서 얻은 기준이 이 프로젝트의 출발점입니다. 자동화가 값이 나오려면 셋 중 하나는 있어야 합니다.

  • 반복이 많다 — 같은 걸 매주 30번
  • 빠뜨리면 손해다 — 잊으면 돈이나 사람이 나간다
  • 흩어진 걸 모아야 한다 — 사람이 하면 30분

문구 쓰기는 셋 다 아니었습니다. 강사료 계산은 셋 다였습니다. 매달 반복되고, 틀리면 강사와 분쟁이고, 카톡 11개에 흩어진 숫자를 모아야 합니다.

2. 병목은 계산이 아니라 옮겨 적기였다

처음엔 "강사료 계산기"를 만들려 했습니다. 그런데 실제로 시간을 잡아먹는 건 계산이 아니었습니다.

월말에 선생님들이 카톡으로 근무시간을 보냅니다. 그걸 하나씩 읽어서 엑셀에 옮겨 칩니다.

계산은 수식이 1초면 합니다. 30분은 옮겨 적는 데 쓰입니다. 그러면 답은 하나입니다. 옮겨 적는 단계를 없애면 됩니다. 강사가 직접 넣게 하면 됩니다.

그래서 이 프로그램의 형태가 '엑셀 파일'에서 '링크'로 바뀌었습니다.

3. 핵심 기술

3-1. 주 단위 재집계 — 주휴수당

가장 까다로웠던 부분입니다. 근무시간은 날짜별로 쌓이는데, 주휴수당은 주 단위로 판단합니다. 월 총합만 가지고는 절대 계산할 수 없습니다.

그래서 월 데이터를 월~일 경계로 다시 자른 뒤, 주마다 따로 판정합니다.

function weeksOf(m){
  const n = daysIn(m), out = []; let cur = [];
  for (let d = 1; d <= n; d++){
    cur.push(d);
    if (dowOf(m, d) === 0 || d === n){ out.push(cur); cur = []; }
  }
  return out;
}

판정식은 이렇습니다. 그 주 근무시간이 15시간 이상이면,

주휴수당 = min(주 근무시간 ÷ 40 × 8, 8시간) × 시급

40시간을 넘겨도 8시간이 상한입니다. 월 40시간을 일한 강사라도 한 주에 몰아서 했는지 4주에 나눠서 했는지에 따라 지급액이 달라집니다. 이게 주 단위로 다시 자르는 이유입니다.

3-2. 역할에 따라 다른 화면

같은 링크 하나인데 두 화면이 나옵니다.

강사 화면 원장 화면
들어가는 법 이름 + 전화 뒷 4자리 비밀번호 4자리
보이는 것 날짜 칸, 본인 합계 시간 11명 전체, 금액, 주휴수당
안 보이는 것 금액, 주휴수당, 남의 기록 —

단가와 주휴수당을 강사가 못 보게 한 건 의도적입니다. 강사끼리 시급이 다른 걸 알게 되는 순간 다른 문제가 시작되기 때문입니다.

다만 솔직히 적어둡니다. 이건 화면에서 가리는 수준이지 암호학적 보안이 아닙니다. 브라우저를 파고들면 못 막습니다. 민감한 정보를 더 넣을 자리는 아닙니다.

3-3. 3.3% 원천징수 절사

사업소득 원천징수는 소득세 3%, 지방소득세 0.3%이고 각각 10원 미만을 버립니다. 합쳐서 3.3%를 한 번에 곱하면 1원 단위가 틀어집니다.

const inc = Math.floor(gross * 0.03  / 10) * 10;  // 소득세
const loc = Math.floor(gross * 0.003 / 10) * 10;  // 지방소득세

3-4. 디바운스 자동 저장

'저장' 버튼을 없앴습니다. 강사가 숫자를 찍을 때마다 0.7초 뒤에 저장됩니다. 화면은 먼저 바뀌고 저장은 뒤따라갑니다.

말일에 몰아 넣으면 대부분 기억에 의존해 씁니다. 수업 끝나고 그날 바로 찍게 만드는 것이 정확도를 올리는 유일한 방법이고, 저장 버튼은 그 흐름을 끊습니다.

3-5. 데이터 구조

roster/<강사id>              이름, 뒷4자리, 구분, 단가, 주휴 대상 여부
hours/<YYYY-MM>__<강사id>    { days: { 1: 3, 2: 2.5, ... } }
config/admin                 원장 비밀번호

월과 강사를 문서 ID에 함께 넣어, 월별 조회가 한 번에 끝나게 했습니다.

4. 만들고 나서 알게 된 것

주휴수당을 사람에 붙이면 안 됩니다. 처음엔 특정 강사 두 명을 대상으로 지정했습니다. 그런데 주휴수당은 사람이 아니라 조건(주 15시간)에 붙는 권리입니다. 조건을 채운 다른 강사에게 안 주면 그게 체불입니다. 지금 코드는 지정 방식이지만, 조건 자동 판정으로 바꾸는 게 맞습니다.

3.3%로 처리한다고 사업소득이 되는 건 아닙니다. 출퇴근 시간이 정해져 있고 원장 지시를 받으면 실질은 근로자로 판단될 수 있습니다. 세금 처리 방식이 신분을 정하지 않습니다.

받은 카톡 원문은 남겨야 합니다. 강사료 분쟁은 대부분 "저는 4시간이라고 보냈는데요"에서 시작합니다. 직접 입력 방식으로 바꾸면 이 문제 자체가 사라집니다. 입력한 사람이 본인이니까요.

5. 실행

git clone https://github.com/daum0809/gangsa-hours.git
cd gangsa-hours
open index.html

의존성 없습니다. HTML 파일 하나입니다. 브라우저에서 바로 열립니다.

써보기

  1. 아래 "원장님이신가요?" → 비밀번호 4자리를 정합니다 (처음 넣은 번호가 등록됩니다)
  2. 강사 명단에서 이름, 전화 뒷 4자리, 구분, 단가를 실제 값으로 바꿉니다
  3. 나가서 강사 이름 + 뒷 4자리로 들어가 날짜 칸에 시간을 찍습니다
  4. 다시 원장 화면에서 계산 결과와 주휴수당 내역을 확인하고 CSV로 내려받습니다

PoC 안내 — 이 공개 버전은 서버 없이 도는 데모라 입력이 브라우저 안에만 저장됩니다. 강사 여러 명이 각자 폰에서 입력하고 원장이 한곳에서 보려면 공유 저장소가 필요합니다. 실제 운영본은 그 부분만 다르고 계산식과 화면은 같습니다.
