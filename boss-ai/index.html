01. 어떤 문제를 풀 것인가

사장이 “매출이 줄었다”고 말할 때 필요한 것은 조언의 양보다 원인을 구분할 정보입니다. 방문객이 줄었는지, 문의가 계약으로 이어지지 않는지, 재구매가 줄었는지에 따라 다음 행동은 달라집니다.

노션 원안의 핵심은 체크인 → 언어화 → 우선순위 하나 → 최소 행동 → 회고입니다. 첫 대상은 소규모 서비스업 대표입니다. PoC는 매출 하락 진단에 집중하며 사업 전체를 자율 운영하거나 원인을 확정하지 않습니다.

02. 모델을 어디에 사용할까

자유로운 한국어 고민을 해석하고 판별 질문을 만드는 역할에 언어모델을 사용합니다. 초기 후보는 GPT-4.1 mini입니다. 구조화 출력 지원을 활용해 결과 항목을 일정하게 만들되, 내용의 정확성은 별도로 검증합니다.

사용 기법은 단계별 프롬프트와 JSON Schema입니다. 아직 파인튜닝·RAG는 사용하지 않습니다. 노션에 정리된 하루질문 OS의 5단계를 화면과 프롬프트에 반영했습니다. 질문집 원문을 검색하는 기능은 없습니다. 모델 문서 · 구조화 출력 문서

03. 사장 앱은 어떻게 작동하나

  1. 체크인: 마음과 강도, 지금 가장 무거운 고민을 적습니다.
  2. 언어화: 사실과 해석을 구분할 질문을 최대 3개 받습니다.
  3. 압축: 답변을 바탕으로 오늘 집중할 문제 하나를 고릅니다.
  4. 최소 행동: 시작 시간과 완료 기준이 있는 30분 이내 행동 하나를 제안합니다.
  5. 저녁 회고: 실행 여부와 장애물을 기록하고 다음 체크인으로 옮기거나 JSON으로 저장합니다.

공개 페이지는 가상 사례 3종을 보여줍니다. 실제 AI 모드는 Python 로컬 서버에 API 키를 설정한 뒤 실행합니다. 키를 공개 웹페이지에 넣지 않으며 서버는 로컬 접속만 허용합니다.

5. 한계·추가 시도가상 체험, 입력 검증, 결과 내보내기, 다음 계획작성·구현

05. 잘 만들었다는 주장은 어떻게 검증할까

같은 모델·같은 정보로 일반 프롬프트와 구조화 진단을 비교합니다. 원인 단정, 근거 없는 숫자, 실행 과제의 구체성, 시간·예산 제약 반영을 사람이 평가합니다. 질문 생성 품질은 별도로 평가해 추가 정보의 효과를 혼동하지 않습니다.

목표이며, 아직 결과가 아닙니다.
  • 10점 품질 평가에서 일반 프롬프트 대비 평균 2점 개선
  • 근거 없는 수치 생성 0건
  • 응답 형식 성공률 95% 이상
  • 사용성 시험에서 5분 이내 행동 계획 1개 작성

6건의 가상 사례만으로 일반화할 수 없습니다. 실제 매출 개선은 별도의 장기 검증 대상입니다.

06. 확인한 것과 남은 것

실제 API 호출 없는 기능 테스트 6개를 통과했습니다. 입력 길이 제한, 키 미설정 오류, 질문 단계 행동 출력 방지, 응답 형식 검사, 예시 표시를 확인했습니다. 이 테스트는 AI 추론 품질이나 응답 정확도를 측정하지 않습니다.

다음 순서는 API 키 설정 후 실호출 → 비교 평가 → 대표 사용자 사용성 시험입니다. 현재 회고는 같은 화면에서 다음 체크인으로 옮길 수 있습니다. 재접속 자동 복원은 이후 과제입니다. 사람이 제공한 기록만으로 원인을 확정하지 않는 원칙을 유지합니다.
